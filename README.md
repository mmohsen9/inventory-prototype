# نظام إدخال حركات المخزون - مساكن رفاء (نموذج أولي Prototype)

نموذج تشغيلي كامل (Flask + SQLite) لإدارة عمليات المشتريات والتحويلات بين المستودع والفروع،
مع بوابة تحقق مسبق من البيانات، مسح Barcode متتابع، طابور ترحيل خلفي، وقاموس ترجمة أخطاء Foodics.

هذا النموذج **محلي بالكامل** (لا يتصل فعلياً بـ Foodics API لأن هذا يتطلب مفاتيح API خاصة بحسابكم).
دالة الترحيل `mock_foodics_api_call()` في ملف `app.py` هي نقطة الاستبدال الوحيدة المطلوبة
لربط النظام فعلياً بـ Foodics عند توفر صلاحيات API — استبدلها باستدعاء `requests.post(...)` الحقيقي.

---

## 1. متطلبات التشغيل

- Python 3.10 أو أحدث.
- لا حاجة لإنترنت لتشغيل النموذج نفسه (يعمل محلياً على الشبكة الداخلية).
- متصفح حديث على الجوال/الآيباد يدعم:
  - الكاميرا (getUserMedia)
  - BarcodeDetector API (مدعوم في Chrome/Edge على أندرويد، وSafari الحديث على آيباد يحتاج بديل — راجع قسم 6).

## 2. التثبيت والتشغيل (على جهاز الكمبيوتر/السيرفر الداخلي)

```bash
cd rafa_inventory_prototype
python -m venv venv
venv\Scripts\activate        # على ويندوز
# أو: source venv/bin/activate  # على ماك/لينكس

pip install -r requirements.txt
python app.py
```

سيعمل النظام على: `http://<عنوان-الجهاز-على-الشبكة>:5000`

مثال: `http://192.168.1.50:5000`

من أجهزة الجوال والآيباد على نفس شبكة الواي فاي، افتح نفس العنوان في المتصفح.

## 3. تحميل البيانات الأولية (مرة واحدة)

```bash
python seed_data.py
```

هذا السكربت يقوم بـ:
- إنشاء قاعدة البيانات `instance/rafa_inventory.db`.
- تحميل قائمة الأصناف من ملف `items_export.csv` (ضع فيه نسخة محدثة من تصدير أصناف فوديكس).
- إنشاء المواقع الأساسية (المستودع الرئيسي + الفروع).
- إنشاء 3 مستخدمين تجريبيين: أمين مستودع، موظف فرع، محاسب.

## 4. المستخدمون التجريبيون بعد التشغيل الأول

| الاسم | الدور | كلمة المرور |
|---|---|---|
| أمين المستودع | warehouse | 1234 |
| موظف الفرع | branch_staff | 1234 |
| المحاسب | accountant | 1234 |

يمكن تغييرها لاحقاً من جدول `users` مباشرة أو بإضافة شاشة إدارة مستخدمين.

## 5. ربط Foodics API الفعلي (الخطوة النهائية بعد استلام الصلاحيات)

في ملف `app.py` ابحث عن الدالة:

```python
def mock_foodics_api_call(payload, endpoint):
    ...
```

استبدل محتواها باستدعاء حقيقي، مثال:

```python
import requests
def foodics_api_call(payload, endpoint):
    headers = {"Authorization": f"Bearer {FOODICS_API_TOKEN}"}
    r = requests.post(f"https://api.foodics.com/v5/{endpoint}", json=payload, headers=headers, timeout=15)
    return r.status_code, r.json()
```

ثم أضف رمز الوصول `FOODICS_API_TOKEN` في متغيرات البيئة أو ملف `.env`.

## 6. ملاحظة حول المسح على الآيباد (Safari)

BarcodeDetector API غير مدعوم افتراضياً في كل إصدارات Safari. الحل المطبق في `static/js/scanner.js`:
- يحاول استخدام BarcodeDetector أولاً (يعمل على Chrome/Edge/أندرويد ومعظم أجهزة آيباد الحديثة مع تفعيل العلم التجريبي).
- إن لم يكن مدعوماً، يظهر تلقائياً حقل إدخال يدوي/قارئ خارجي (USB أو Bluetooth Barcode Scanner يعمل كلوحة مفاتيح)، وهو الحل الأكثر استقراراً للاستخدام اليومي في المستودع.

**التوصية العملية:** لأمين المستودع، يُفضّل شراء قارئ Barcode لاسلكي (Bluetooth HID) يعمل كلوحة مفاتيح خارجية — يعمل مع أي متصفح ومع أي جهاز فوراً دون مشاكل توافقية.

## 7. هيكل المشروع

```

├── app.py                  # التطبيق الرئيسي (Flask) - كل المسارات والمنطق
├── models.py                # نماذج قاعدة البيانات (SQLAlchemy)
├── validation_gate.py       # منطق بوابة التحقق المسبق (SKU/الوحدة/المرفقات)
├── sync_queue.py             # طابور الترحيل الخلفي + قاموس ترجمة الأخطاء

├── requirements.txt
├── items_export.csv          # ضع هنا آخر تصدير لأصناف فوديكس (نسخة من ملفك الحالي)
├── templates/                # شاشات الواجهة (HTML متجاوب)
├── static/css/style.css      # تصميم متجاوب (جوال/آيباد)
├── static/js/scanner.js       # منطق المسح المتتابع للـ Barcode
├── static/js/app.js           # القيم الافتراضية + رفع المرفقات + طابور محلي عند انقطاع الشبكة
└── uploads/                   # مكان حفظ الصور محلياً (يُستبدل لاحقاً برفع Google Drive الفعلي)
```

## 8. ربط رفع الصور بـ Google Drive الفعلي

حالياً الصور تُحفظ في مجلد `uploads/` محلياً وتُخزَّن كرابط محلي في قاعدة البيانات (لتشغيل النموذج بدون مفاتيح API خارجية).
للربط الفعلي بـ Google Drive، استبدل الدالة `save_attachment()` في `app.py` باستخدام Google Drive API
(`google-api-python-client`) لرفع الملف والحصول على رابط مشاركة، ثم احفظ الرابط الناتج بدلاً من المسار المحلي.

## 9. الخطوات التالية بعد تجربة هذا النموذج

1. تجربة النموذج داخلياً مع أمين المستودع وفرع واحد لمدة أسبوع.
2. تسجيل أي ملاحظات تشغيلية (حقول ناقصة، خطوات بطيئة، رسائل غير واضحة).
3. طلب صلاحيات Foodics API الفعلية واستبدال `mock_foodics_api_call`.
4. ربط رفع الصور بـ Google Drive الفعلي.
5. تعميم النظام على باقي الفروع.
