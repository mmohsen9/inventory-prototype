# قاعدة حظر التعديل على بيانات فوديكس (Foodics Read-Only Rule)

## الغرض
حماية الحساب والبيانات الأصلية في فوديكس (Foodics Production Live Account) من أي تعديل أو مساس أو حذف غير مقصود.

## نطاق القاعدة والتعليمات الإلزامية:
1. **القراءة والاطلاع والمزامنة الواردة (Read-Only Inspection):**
   - التعامل البرمجي مع Foodics API v5 يرتكز على استعلامات القراءة والمطابقة (`GET` requests):
     - قراءة الفروع والمستودعات (`GET /v5/branches`, `GET /v5/warehouses`).
     - قراءة أصناف ومواد المخزون وتكاليفها المعتمدة (`GET /v5/inventory_items`).
     - قراءة الموردين وربطهم بالأصناف (`GET /v5/suppliers`).
     - قراءة حركات استهلاك مبيعات الكاشير للوصفات (`GET /v5/inventory_transactions?filter[type]=8`).
     - قراءة معلومات النشاط والمصادقة (`GET /v5/whoami`).

2. **إنشاء مسودات المشتريات والتحويلات حصراً (Drafts Only):**
   - يُسمح بإنشاء وثائق ترحيل جديدة بحالة مسودة (Draft status = 1) فقط دون التأثير المباشر على الأرصدة الحية إلا بعد الاعتماد اليدوي في فوديكس، وذلك عبر مسار حركات المخزون الرسمي:
     - سند الاستلام: ترحيل كفاتورة مشتريات مسودة إلى قسم **الشراء** في فوديكس (`POST /v5/inventory_transactions` مع `type: 1` و `status: 1` لإنشاء وثيقة `PUR-...` مسودة).
     - سند صرف المواد: ترحيل كتحويل صادر مسودة إلى **تحويلات المخزون** في فوديكس (`POST /v5/inventory_transactions` مع `type: 2` و `status: 1` لإنشاء وثيقة `TRS-...` مسودة).

3. **حظر كامل لأي تعديل أو حذف في فوديكس:**
   - يُمنع منعاً باتاً استدعاء أي عمليات تعديل أو تغيير أو حذف على خوادم فوديكس:
     - ممنوع إرسال طلبات `PUT`, `PATCH`, `DELETE` إلى أي من موارد فوديكس (كالأصناف، الأسعار، الفروع، الموردين، أو الإعدادات).
     - ممنوع تعديل أسعار أو وصفات أو مسميات أو وحدات الأصناف في فوديكس عبر الـ API.

4. **حفظ ومطابقة البيانات داخل النظام المحلي:**
   - فوديكس هو «المصدر المرجعي الرئيسي للأصناف والفروع ومبيعات نقاط البيع» (Source of Truth).
   - يتم جلب التغييرات وتحديث قاعدة البيانات المحلية (`SQLite`) دون المساس ببيانات فوديكس على الإطلاق.
